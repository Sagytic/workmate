DESKTOP MINI / WINDOWS

먼저, 바탕화면에 나만의 비서를 두세요.

Windows용 Workmate Mini가 바탕화면과 트레이에 머뭅니다. 작은 모아를 누르거나 Ctrl + Alt + Space로 대화창을 열어 바로 요청하세요.

Windows 64-bit

바탕화면 모아

상단 점을 끌어 위치를 바꾸고, 항상 위 표시를 켜거나 끕니다. 대화창을 닫으면 트레이에 남고, 트레이 메뉴에서 완전히 종료합니다.

필요한 순간의 알림

확인할 업무는 작은 말풍선으로 표시합니다. 집중 시간과 알림 쉬기 설정을 함께 적용하며, 알림이 다른 창의 입력을 가로채지 않습니다.

로그인과 함께 시작

설정에서 Windows 로그인 시 시작을 켤 수 있습니다. 서버가 실행 중이면 연결하고, 꺼져 있으면 Mini가 로컬 서버를 함께 시작합니다.

설치형 Mini는 이 PC의 워크스페이스에 연결합니다. Windows가 꺼져 있거나 Mini와 서버가 모두 종료된 동안에는 작업이 실행되지 않습니다. 다른 PC에서는 Python과 업무앱 실행 의존성을 먼저 준비하세요.

Windows에서 시작하기

  1. Windows Mini 패키지를 내려받고 압축을 모두 풉니다.
  2. Python 3.11 이상과 Node.js 22.12 이상을 준비하고 workmate/setup.ps1을 실행합니다.
  3. Workmate_Mini_실행.cmd를 실행합니다. 로컬 서버가 꺼져 있으면 Mini가 함께 시작합니다.
  4. 모아를 누르거나 Ctrl + Alt + Space로 빠른 대화를 엽니다. 창을 닫아도 Mini는 트레이에 남습니다.
  5. 트레이에서 항상 위 표시·알림·Windows 로그인 시 시작을 조정합니다. 완전히 종료하려면 Workmate Mini 종료를 선택합니다. Mini가 자동 시작한 서버도 함께 종료되며, 별도로 실행한 서버는 유지됩니다.

웹 워크스페이스만 열었을 때는 웹 안의 모아를 사용합니다. 바탕화면 상주 기능은 Windows Mini를 실행해 사용합니다. PC 전원이 꺼져 있거나 Mini와 서버가 모두 종료된 동안에는 실행되지 않습니다.

GET STARTED / YOUR OWN MODEL

내 API로 연결하고 시작하세요.

Workmate는 개인이 사용하는 OpenAI 호환 LLM을 연결합니다. 준비할 것은 API 기본 주소, API 키, 모델 ID 세 가지입니다.

  1. 워크스페이스 오른쪽 위의 API 연결됨 · 모델 설정됨 · 규칙 기반 배지를 누릅니다.
  2. API 제공자를 선택하거나 직접 입력합니다. 기본 주소는 https://제공자주소/v1처럼 제공자가 안내한 경로까지 입력합니다.
  3. 발급받은 API 키와 정확한 모델 ID를 입력합니다. 비밀번호나 일반 서비스 로그인 정보를 입력하는 칸이 아닙니다.
  4. 연결 확인 후 적용을 누릅니다. 짧은 실제 요청에 성공한 경우에만 새 설정을 적용합니다.
  5. 설치형에서 다음 실행에도 사용할 경우 이 PC에 저장을 선택합니다. 키는 프로젝트의 .env에 저장되며, 화면이나 자료 묶음에 다시 표시하지 않습니다.
온라인에서는 방문 세션마다 자신의 API를 연결합니다. 키는 해당 세션의 서버 메모리에만 보관하며, 서버 재시작 시 다시 연결합니다. 브라우저 저장소와 GitHub에 키를 기록하지 않습니다. API 사용료는 연결한 제공자의 계정에 청구될 수 있습니다.

호환 조건은 /chat/completions, Bearer 인증, JSON 객체 응답(response_format: json_object)입니다. Azure 전용 또는 Anthropic 원본 API는 OpenAI 호환 게이트웨이를 이용하세요. 온라인 연결은 OpenAI·OpenRouter·DeepSeek·Groq·Mistral·Google의 공개 호환 주소로 제한하며 개인 서버 주소는 설치형에서 이용합니다.

연결이 되지 않을 때

401 키와 제공자 일치 여부 · 402 잔액·한도 · 404 주소와 모델 ID · 429 요청 제한을 확인하세요. JSON 응답 오류는 모델의 구조화 응답 지원과 추론 설정을 확인합니다. 설치형의 localhost 주소는 Workmate 서버가 실행되는 PC를 뜻합니다.

.env 파일로 직접 설정하기

프로젝트의 .env.example을 .env로 복사해 아래 세 값을 채운 뒤 서버를 다시 시작합니다. 환경 변수로 전달한 값이 파일보다 우선합니다.

WORKMATE_LLM_BASE_URL=https://your-provider.example/v1
WORKMATE_LLM_API_KEY=여기에_개인_API_키
WORKMATE_LLM_MODEL=제공자의_모델_ID

.env 파일은 공유하지 않습니다. 현재 연결 해제는 실행 중 연결만 해제하므로 저장한 설정을 없애려면 .env에서 해당 값을 지우고 서버를 다시 시작하세요.

PERSONAL DESK / ONE CONTEXT, FOUR HABITS

비서 데스크: 오늘의 맥락을 다음 행동으로

왼쪽 비서 데스크의 네 탭에서 브리핑, 후속 연락, 나의 루틴, 내 글쓰기를 사용합니다. 새 역할을 여러 개 더 만드는 대신 기존 8개 전문 분야에 개인화와 지속적인 업무 상태를 연결합니다.

1. 오늘의 브리핑

  1. 메일·일정 연결에서 사용할 자료를 가져옵니다. 아래 Google·Microsoft 설정 또는 EML·ICS 파일 가져오기를 사용합니다.
  2. 오늘의 브리핑에서 기준 날짜·프로젝트·참고 자료를 선택하고 브리핑 만들기를 누릅니다. 자료를 선택하지 않으면 해당 프로젝트, 프로젝트도 비어 있으면 이 작업 공간에서 가져온 메일·일정을 사용합니다.
  3. 기한 경과·오늘 마감 업무, 메일 사본, 해당 날짜와 겹치는 일정을 확인합니다. 업무는 선택 프로젝트 또는 작업 공간의 실제 기록을 사용합니다.
  4. 원문 보기 또는 업무 보기로 근거를 확인합니다. 답장 준비·회의 준비·후속 연락·집중 계획을 선택하면 참고 자료가 입력된 에이전트 설정을 엽니다. 설정을 확인·저장한 뒤 실행합니다.
브리핑 집계와 예약 실행에는 LLM 호출이 필요하지 않습니다. 메일 상세는 최근 사본 20건, 일정 50건, 기한 있는 업무 100건까지 표시하며 전체 범위 집계와 생략 안내를 함께 제공합니다. 브리핑 기록은 최근 30개를 보관합니다. 시간대가 불확실하거나 반복 일정이 펼쳐지지 않은 자료는 날짜별 일정에서 제외하고 알립니다. 종일 기한은 날짜로 유지하며 다음 날부터 기한 경과입니다. 외국 캘린더의 종일 일정은 원래 날짜·시간대와 한국 시간 기준의 겹침을 구분합니다.

2. 후속 연락

  1. 후속 연락에서 챙길 내용, 참고 원문, 내가 답할 일 / 답변을 기다리는 일, 필요하면 기한과 메모를 입력합니다.
  2. 연락 등록을 누르면 선택한 원문과 함께 보드에 남습니다. 같은 열린 항목을 반복 등록하면 기존 기록을 사용합니다.
  3. 내일 9시로 미루거나 지금 확인으로 되돌립니다. 미룬 시각이 지나면 서버 실행 중 모아 알림을 한 번 표시합니다.
  4. 실제 처리 여부를 확인한 뒤 완료로 표시합니다. 완료한 연락을 다시 열거나, 필요 없는 항목을 보관하여 활성 목록에서 제외합니다.

방향·완료 상태는 사용자가 정한 관리 기록입니다. 가져온 일부 사본만으로 전체 대화 이력이나 상대의 미회신을 단정하지 않습니다. 메일을 보내거나 읽음·라벨 상태를 바꾸지 않습니다. 활성 연락은 100개까지 저장합니다.

3. 나의 루틴

  1. 나의 루틴에서 이름, 한국 시간 기준 실행 시각, 반복 요일, 프로젝트·자료 범위를 저장합니다.
  2. 지금 실행으로 결과를 바로 확인하거나 예약 시간에 생성된 브리핑을 엽니다.
  3. 예약이 실행되면 모아가 비서 데스크로 연결되는 알림을 표시합니다. 같은 예약의 알림을 중복 생성하지 않습니다.
  4. 일시 정지 / 다시 시작으로 조절하고, 사용하지 않는 루틴은 보관합니다. 보관한 정의와 기존 결과는 남고 다음 예약은 중단됩니다.
서버와 해당 작업 공간이 실행 중일 때만 작동합니다. 서버가 꺼진 이전 날짜의 예약을 몰아서 실행하지 않습니다. 루틴은 저장된 사본을 읽으며 Google·Microsoft를 자동 조회하지 않습니다. 외부 계정의 새 자료는 연결 화면에서 갱신하세요. 루틴은 30개까지 활성 목록에 저장할 수 있습니다.

4. 내 글쓰기

  1. 내 글쓰기에서 말투, 언어, 길이, 서명을 입력합니다. 표현 추가로 상용구 이름과 문장을 최대 12개 저장합니다.
  2. 글쓰기 설정 사용을 켜고 저장합니다.
  3. 개인 LLM API를 연결한 뒤 메일 정리·답장 초안 또는 약속·후속 연락 에이전트를 실행합니다. 해당 실행에 저장된 설정의 사본을 참고합니다.
  4. 받는 사람·약속·날짜·표현을 확인하고 EML을 메일 앱에서 직접 전송합니다.

설정은 표현을 위한 지침이며 원문에 없는 사실을 추가하는 근거가 아닙니다. 사용을 끄면 후속 실행에 포함하지 않습니다. 이미 완료된 답장이나 과거 실행의 설정은 바뀌지 않습니다.

GMAIL & GOOGLE CALENDAR

내 Google 앱으로 메일·일정 읽기 연결

메일·일정 연결 → Google에서 Gmail과 Google Calendar를 연결합니다. 읽기 커넥터는 구현되어 있으며, 실제 사용에는 본인의 Google Cloud 앱 등록과 Google 로그인·동의가 필요합니다. Microsoft 연결의 조직 승인과는 별개입니다.

배포 관리자가 승인된 Google 웹 앱의 WORKMATE_GOOGLE_CLIENT_ID와 WORKMATE_GOOGLE_CLIENT_SECRET을 서버에 설정할 수도 있습니다. 이 경우 방문자는 비밀값을 입력하지 않고 Google 연결 버튼으로 각자 로그인·동의합니다. 현재 공개 서비스에는 공용 Google 앱이 등록되어 있지 않아 본인의 앱 설정이 필요합니다. 직접 설정한 값으로 덮어쓸 수 있으며 계정 토큰은 여전히 방문자별로 분리됩니다.

Google Cloud 준비

  1. Google Cloud Console에서 본인의 프로젝트를 선택하고 Gmail API, Google Calendar API를 사용 설정합니다.
  2. Google Auth Platform의 브랜딩·대상 사용자·데이터 액세스를 설정합니다. 조직 전용 Internal 앱은 해당 조직 정책을 따릅니다. External 앱의 게시 상태가 Testing이면 사용할 계정을 허용 사용자에 등록합니다.
  3. Clients → Create client → Web application을 선택합니다. Workmate의 Google 설정에 표시된 callback 주소를 Authorized redirect URIs에 정확히 등록합니다.
  4. 온라인은 https://workmate-otpo.onrender.com/api/google/auth/callback, 로컬 기본 실행은 http://127.0.0.1:8765/api/google/auth/callback입니다. 실제 사용 화면에 표시된 주소와 포트가 일치해야 합니다.
  5. Client ID와 client secret을 Workmate 설정에 입력하고 저장합니다. Google 비밀번호를 입력하는 곳이 아니며, 값은 공개 문서나 저장소에 붙여 넣지 않습니다.
  6. Google 연결을 눌러 같은 브라우저에서 Google 로그인과 동의를 완료합니다. 앱 이름과 읽기 권한을 확인하면 원래 작업 공간으로 돌아옵니다.

연결한 자료 선택

  1. Gmail에서 메일 불러오기로 받은편지함 목록을 읽습니다. 화면 검색은 이번에 불러온 목록 안에서 제목·본문·보낸 사람을 찾으며 Gmail 전체 검색 명령이 아닙니다.
  2. Google Calendar에서 앞으로 7·14·30·90일, 이번 달·다음 달 전체, 기간 지정 중 하나를 골라 기본 캘린더 일정을 불러옵니다. 기간 지정은 한국 날짜 기준으로 종료일을 포함해 최대 366일까지 조회합니다. 이후 달의 일정은 다음 달 전체 또는 기간 지정을 선택하세요. 목록 제한으로 더 많은 항목이 있으면 안내합니다.
  3. 필요한 항목과 프로젝트를 선택해 자료실에 가져옵니다. 같고 변하지 않은 원문은 중복 저장하지 않으며 변경된 원문은 새 사본으로 남습니다.
  4. 비서 데스크의 브리핑 또는 전문 에이전트의 참고 자료로 연결합니다. 원문은 가져온 시점의 사본입니다.
Gmail 읽기는 Google의 restricted scope입니다. 공개 배포·데이터 처리 방식에 따라 앱 검증 또는 보안 평가가 필요할 수 있으며, 개인 앱이라고 자동 면제되는 것은 아닙니다. External 앱이 Testing 상태이면 이 권한의 갱신 토큰은 일반적으로 7일 후 만료되어 재연결이 필요합니다. 조직 정책이나 사용자 동의 제한이 있으면 관리자가 승인해야 합니다.

연결 정보와 개인 자료

Google client secret·접근 토큰·갱신 토큰은 해당 작업 공간의 서버 메모리에만 둡니다. 브라우저 저장소·SQLite·공유 파일에 영구 저장하지 않으며 서버 재시작·세션 만료 후 다시 연결합니다. 개인이 직접 입력한 설정은 다시 입력하고, 서버의 기본 앱이 있으면 각자 로그인·동의를 다시 진행합니다. 연결 해제는 계정 접근을 끝내지만 이미 자료실에 저장한 사본은 별도로 관리합니다. 계정 조회만으로 LLM을 호출하지 않습니다. 사용자가 전문 분석을 실행할 때 선택한 원문이 개인 LLM 제공자로 전달될 수 있습니다.

메일 전송·초안 서버 저장·메일 라벨 변경·외부 일정 생성은 수행하지 않습니다. 아래 메일·일정 영상 후반부에서 Google Calendar의 다음 달 전체·기간 지정 조회와 항목 선택을 확인할 수 있습니다. 목록 조회만으로 자료실에 저장되지는 않으며, 필요한 항목을 선택한 뒤 가져오기를 실행합니다.

Microsoft 계정을 연결하기 전에

Microsoft 로그인과 조직 승인이 필요합니다. 회사에서 승인한 Microsoft Entra 앱의 클라이언트 ID와 테넌트 ID를 준비하세요. Workmate의 코드 로그인은 Microsoft의 위임된 권한을 사용합니다. Microsoft 비밀번호나 클라이언트 암호를 Workmate에 입력하지 않습니다.

  1. Microsoft Entra 관리 센터의 앱 등록 → 새 등록에서 회사 정책에 맞는 계정 유형으로 등록합니다. 등록 권한이 없으면 조직 관리자에게 요청합니다.
  2. 인증 → 고급 설정 → 공용 클라이언트 흐름 허용을 예로 설정하고 저장합니다. 이 코드 로그인 방식 자체에는 리디렉션 URI나 클라이언트 암호가 필요하지 않습니다.
  3. API 권한 → Microsoft Graph → 위임된 권한에서 User.Read, Mail.Read, Calendars.Read를 설정합니다. 조직에서 요구하면 관리자 동의를 받습니다.
  4. 개요의 애플리케이션(클라이언트) ID와 디렉터리(테넌트) ID를 Workmate의 연결 설정에 입력합니다. 여러 조직 또는 개인 Microsoft 계정은 앱에 등록한 지원 계정 유형과 일치해야 합니다.
  5. Workmate에서 연결을 시작합니다. 표시된 Microsoft 인증 주소를 열고, 본인이 방금 시작한 코드를 입력합니다. 인증 화면의 앱 이름과 요청 권한을 확인한 뒤 로그인합니다.
  6. Workmate에 연결된 계정이 표시되면 메일·일정을 조회하고 가져올 항목을 직접 선택합니다.

접근·갱신 토큰은 해당 방문자의 서버 세션 메모리에만 유지합니다. 서버 재시작이나 세션 만료 후에는 다시 연결합니다. 연결 해제는 Microsoft 연결을 종료하며, 이미 선택해 자료실에 저장한 문서는 별도로 관리합니다. 필요 없는 자료는 자료실에서 삭제하세요. 에이전트 분석을 실행하면 선택한 원문은 사용자가 연결한 LLM API로 전달될 수 있습니다.

현재 안내와 영상은 EML·ICS 파일을 가져와 실행한 결과를 포함합니다. 조직에서 앱 등록을 허용하지 않으면 Microsoft 연결은 관리자 승인 후 진행하고 파일 가져오기를 사용할 수 있습니다. 실제 Microsoft 계정의 로그인·동의 결과는 사용자가 연결할 때 확인합니다.

MCP CONNECTIONS

내 에이전트와 만든 자료를 MCP로 제공하기

왼쪽 MCP 연결에서 외부 AI 도구에 제공할 항목을 선택합니다. MCP는 다른 프로그램이 Workmate의 도구와 자료를 정해진 방식으로 호출하는 연결 규격입니다.

  1. 연결 만들기에서 이름과 만료 기간을 정합니다.
  2. 기본·맞춤 에이전트, 문서, 업무앱, Excel 검사에 쓸 파일 중 필요한 항목만 고릅니다.
  3. 에이전트의 내부 자료를 함께 사용할지 확인합니다. 기본값은 외부 요청문만 사용합니다. 맥락 포함을 선택하면 선택한 에이전트 프로필에 연결된 자료·프로젝트 업무·허용된 기억·작성 선호를 발급 시점의 사본으로 포함합니다. 이 범위는 아래에서 별도로 고른 문서 목록보다 넓을 수 있습니다.
  4. 발급된 접근 키를 안전한 곳에 보관합니다. 키 원문은 발급할 때 한 번만 표시됩니다.
  5. 클라이언트에 서버 주소와 Authorization: Bearer <접근 키> 헤더를 입력합니다. URL에 키를 붙이지 않습니다.
  6. 도구 목록에서 허용한 에이전트를 실행하거나 선택한 문서를 읽습니다. 실행 식별자로 진행 상태와 결과를 조회하고 Workmate 호출 기록에서도 확인합니다.

키와 공개 범위 관리

공개된 에이전트의 지침과 허용 맥락은 공개 시점의 설정을 사용합니다. 별도로 선택한 문서와 업무앱은 허용한 ID 범위 안의 최신 내용을 읽습니다. 프로필을 수정한 뒤 바뀐 내용을 제공하려면 새 연결을 만드세요. 키 재발급은 이전 키와 그 키로 시작한 실행의 MCP 조회 권한을 무효화합니다. 새 키는 새로 시작한 실행만 조회할 수 있습니다. 철회·만료된 키로는 목록이나 결과도 조회할 수 없습니다. 키에는 해당 연결의 권한이 있으므로 공유 대상과 보관 위치를 직접 관리하세요.

온라인 작업 공간은 방문 세션 단위입니다. 세션 만료·서버 재시작·재배포 후에는 작업 공간과 연결을 다시 준비해야 합니다. 로컬은 현재 PC의 서버가 실행되어 있어야 합니다. 실행에 LLM이 필요하면 워크스페이스에 연결한 개인 API를 사용하며 제공자의 사용료가 적용될 수 있습니다. MCP 연결이 Google·Microsoft 계정의 비밀키나 접근 토큰을 제공하지는 않습니다.

전문 분야이럴 때 사용하세요확인할 결과

주간 회고업무·학습·개인 목표를 돌아볼 때최근 완료 기록, 다음 행동, 기억 후보

1. 먼저 한 번 실행해 보기

  1. 전문 에이전트를 선택하고 개별 요청을 엽니다.
  2. 바로 시작하기에서 예시를 선택하거나 회의 메모·선택지·개인 기록을 붙여 넣습니다.
  3. 에이전트 실행을 누릅니다. 실행 과정에서 자료 수집, 전문 분석, 근거 확인, 결과 전달 상태를 확인합니다.
  4. 결과 · 다음 행동에서 결정과 후속 업무를 읽고, 참고 근거에서 실행에 사용한 원문과 인용 확인 기록을 봅니다.
  5. 결과 받기를 누르면 요청·결과·원문을 담은 HTML 결과서를 내려받습니다.

2. 선택한 결과만 저장하기

  1. 다음 행동에서 필요한 항목을 체크하고 선택한 업무 등록을 누릅니다. 오늘의 업무에 미완료 업무로 추가됩니다.
  2. 다음에도 기억할 내용에서 확인한 항목을 체크한 뒤 선택한 기억 저장을 누릅니다.
  3. 같은 결과 항목을 다시 선택해도 중복 생성하지 않습니다. 같은 이름의 기억에 다른 내용이 이미 있으면 기존 내용을 유지하고 충돌을 알립니다. 내 업무 기억에서 직접 확인하세요.
기한과 담당자가 명시되지 않은 항목은 비워 둡니다. 날짜만 입력한 기한에는 임의 시각을 붙이지 않습니다. 원문에서 확인되지 않은 기한·담당자는 결과에서 제거하며, 인용이 확인되지 않은 기억 후보는 저장할 수 없습니다.

3. 내 방식의 프로필 만들기

  1. 에이전트 만들기를 눌러 이름, 전문 분야, 소개와 작업 지침을 입력합니다. 기존 카드의 설정을 수정하거나 선택한 에이전트 복제로 시작해도 됩니다.
  2. 프로젝트와 참고 자료를 정합니다. 문서는 최대 20개 선택하며, 프로젝트를 지정하면 같은 프로젝트 자료를 선택합니다.
  3. 선호와 원칙을 분석에 반영하려면 저장된 업무 기억 참고를 켜고 설정 저장을 누릅니다.
  4. 다음 실행부터 저장한 설정을 사용합니다. 이전 실행은 당시의 설정과 자료 사본을 유지합니다. 프로필을 보관해도 이전 결과는 남습니다.

프로젝트를 지정하고 문서를 따로 선택하지 않으면 해당 프로젝트의 자료를 사용합니다. 프로젝트와 문서를 모두 선택하지 않은 회의·의사결정 실행은 요청문을 기준으로 처리하며, 레이더·회고·후속 연락·집중 계획은 등록된 업무를 함께 참고합니다. 메일과 일정은 자료실로 가져온 뒤 참고 자료로 선택하세요. 업무 기억은 사용을 켠 경우에만 분석에 포함합니다. 긴 자료나 많은 기록은 포함한 범위와 제한을 결과에 표시합니다.

작업 지침은 API 연결 시 모델 분석에 반영합니다. API가 없을 때에는 선택한 전문 분야와 자료 범위에 따라 명시 문장을 추출하고 업무 기록을 집계합니다. 임의의 웹사이트 접속·파일 조작·메일 발송 지침을 수행하는 범용 실행기는 아닙니다.

4. 여러 에이전트에게 같은 목표 맡기기

  1. 협업 미션을 선택하고 미션 이름과 공통 목표를 입력합니다.
  2. 함께 실행할 에이전트를 최대 4개 선택합니다. 예를 들어 회의 후속 정리·의사결정 브리프·프로젝트 레이더를 함께 선택합니다.
  3. 미션 맡기기를 누릅니다. 각 프로필은 같은 요청을 자신의 분야와 참고 범위로 독립 실행합니다.
  4. 미션의 에이전트 카드를 눌러 개별 결과·근거·실행 과정을 확인합니다. 후속 업무 등록과 기억 저장은 각 결과에서 선택합니다.

미션은 전문 분야별 실행과 결과를 묶어 보여 줍니다. 에이전트끼리 임의로 메시지를 보내거나 끝없이 작업을 추가하지 않습니다. 공개 서버의 실행 여유가 없으면 진행 중인 작업이 끝난 뒤 다시 실행하세요.

현재는 개인 전용 비서입니다. 온라인은 방문자별 자료·파일·연결을 분리하는 방식이며, 회원가입·사용자별 영속 DB 연동은 향후 확장 범위입니다. 현재 로그인 계정으로 여러 기기의 업무를 이어가거나 영구 복원하는 기능은 제공하지 않습니다.

방문 세션은 비활성 1시간 뒤 정리됩니다. 무료 서버 재시작·재배포·휴면으로 자료와 연결이 초기화될 수 있으므로 결과서를 내려받으세요. Google·Microsoft 연결 계정과 Workmate 방문 세션은 서로 다른 개념입니다. 로컬 설치형은 이 PC의 저장소에 업무를 보관합니다.

실행과 보관

온라인에서는 워크스페이스를 바로 엽니다. 내 PC에 설치하려면 실행 패키지를 내려받아 압축을 모두 풀고 workmate 폴더의 setup.ps1을 실행한 뒤 start.cmd를 실행합니다. 설치형 주소는 http://127.0.0.1:8765/입니다. 자세한 절차는 GitHub README에 있습니다. 처음 사용할 때 위의 개인 API 연결 절차를 진행합니다. Windows에서는 Workmate_Mini_실행.cmd 또는 Workmate Mini.exe로 비서를 시작합니다. Python 의존성과 화면 빌드는 setup.ps1에서 준비합니다.

설치형은 브라우저를 닫아도 저장된 작업이 남습니다. 온라인 저장 기간은 위 안내를 확인하세요. 서버가 꺼진 동안에는 주기 자동화와 기한 알림이 실행되지 않습니다.
