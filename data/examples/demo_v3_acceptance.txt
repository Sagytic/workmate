[업무 예제] 업무 앱 인수 검수 기준
가상 프로젝트의 검수 준비 자료입니다. 아래 기준은 테스트 계획이며 어떤 기능이 실제 통과했다는 결과가 아닙니다.

[A-01] 인수 범위
검수 대상은 입력 화면, 서버 검증, 데이터 저장, 수정과 삭제, 검색, CSV 내보내기이다. 외부 ERP 연동, 운영 배포와 다중 사용자 권한은 현재 구현 범위에 포함하지 않는다. 사용자가 요청한 기능과 구현 범위가 다르면 제한을 먼저 표시한다.

[A-02] 입력 경계값
필수 텍스트의 빈값과 공백, 숫자의 0과 최솟값·최댓값 경계, 잘못된 이메일, 선택지 외 값과 체크 여부를 확인한다. 화면에서 차단되어도 같은 입력을 API로 보냈을 때 허용되면 결함이다. 유효한 0을 누락 값으로 취급하지 않는다.

[A-03] 완료 처리
완료 메모 필수 기능이 켜진 경우 완료 상태에서 메모가 없으면 저장할 수 없어야 한다. 대기와 진행 상태에서는 요청한 규칙에 맞게 동작한다. 과거 데이터가 새 규칙을 만족하지 않으면 자동으로 내용을 만들어 채우지 않고 보완 대상으로 남긴다.

[A-04] 저장과 재실행
새 레코드가 서버에 저장되고 페이지를 다시 열어도 유지되는지 확인한다. 수정은 기존 식별자를 유지하고 삭제는 해당 앱의 레코드에만 적용한다. 자동화 재실행은 같은 업무 결과를 중복 등록하지 않아야 하며 대상 앱이 달라지면 구분한다.

[A-05] 증거와 판정
UAT 기록에는 요구사항, 사전조건, 실행 절차, 기대 결과, 실제 결과, 판정과 화면 증거를 넣는다. 브라우저 테스트를 실행할 수 없으면 미실행으로 남긴다. 테스트 대상 소스 버전과 실제 반영 버전이 같아야 하며 최종 인수 승인은 업무 담당자가 별도로 한다.
