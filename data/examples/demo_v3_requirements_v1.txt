[업무 예제] 고객 포털 요청 관리 요구사항 v1.0
고객 포털 요청 관리의 최초 검토 기준을 정리한 업무 예제입니다. 문단 번호를 답변과 검토 의견의 출처로 사용할 수 있습니다.

[R1-01] 범위와 기준 버전
고객 포털은 내부 실무자가 고객의 개선 요청과 오류 문의를 접수하는 업무 도구이다. 본 문서는 최초 검토안 v1.0이며 후속 변경안이 승인되면 이전 규칙과의 차이를 확인해야 한다. 1차 범위는 요청 등록, 담당자 배정, 목록 검색, 상태 변경과 CSV 내보내기이다. 고객에게 자동으로 이메일을 발송하는 기능과 ERP 자동 반영은 범위에 포함하지 않는다.

[R1-02] 접수 항목
요청 제목, 요청 구분과 업무 모듈은 필수이다. 담당자와 마감일은 접수 시 선택 입력으로 두고, 아직 담당자가 배정되지 않은 요청도 저장할 수 있다. 요청 구분은 개선, 오류, 문의로 제한한다. 고객 연락처는 선택 입력이며 이메일 형식 검사를 적용한다. 예상 공수는 시간 단위로 기록하고 0 이상 160 이하를 허용한다.

[R1-03] 상태 전이와 완료 처리
기본 상태는 대기, 진행, 완료의 세 가지이다. 진행에서 완료로 전환할 때 완료 메모는 선택 입력이다. 완료 후 내용을 수정할 경우 기존 요청 식별자는 유지한다. 상태 변경 이력은 별도 감사 항목으로 검토하되, 이번 검토안에서는 사용자 화면에 상태 이력 화면을 요구하지 않는다.

[R1-04] 응답 기준
일반 요청은 접수 후 2영업일 이내에 담당자를 배정하고 첫 답변 초안을 작성한다. 긴급 요청의 별도 구분과 시간 단위 SLA는 아직 정의하지 않았다. 주말과 공휴일의 영업일 판단은 운영 담당자가 검토한다. 이 수치는 검토 기준이며 고객 계약에 반영할 서비스 수준은 별도로 확정한다.

[R1-05] 조회와 검수
목록은 요청 제목의 키워드와 상태로 검색한다. 담당자별 필터, 마감 임박 필터와 고객별 통계는 후속 후보이다. UAT는 제목 누락 차단, 허용 상태 저장, 숫자 공수 범위, 이메일 형식과 CSV의 한글 보존을 확인한다. 화면 캡처와 실제 결과가 없는 항목은 통과로 기록하지 않는다.

[R1-06] 인수 자료
개발팀은 요구사항 번호와 화면 기능의 대응표, API 입력 검증 목록, 미해결 이슈와 되돌리기 절차를 제출한다. 업무 담당자는 실제 테스트 결과를 확인한 뒤 별도로 인수 여부를 결정한다. 이 문서 자체는 인수 승인이나 테스트 성공의 증빙이 아니다.
