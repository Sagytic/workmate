[업무 예제] 고객 포털 요청 관리 요구사항 v2.0 변경 검토안
v1.0과 비교할 변경 제안입니다. 아래 변경 사항은 승인 여부와 운영 반영 여부를 구분하여 검토합니다.

[R2-01] 변경 배경과 적용 범위
요청의 담당자 공백과 완료 근거 누락을 줄이기 위해 접수 및 완료 조건을 강화한다. v1.0의 요청 등록, 담당자 배정, 목록 검색, 상태 변경과 CSV 내보내기 범위는 유지한다. 변경 번호는 CR-07이며 업무 책임자의 최종 승인 후 적용한다. 승인 전에는 새 규칙을 운영 기준으로 단정하지 않는다.

[R2-02] 접수 입력 변경
요청 제목, 요청 구분, 업무 모듈에 더해 담당자와 마감일을 필수로 입력한다. 기존 요청 중 담당자 또는 마감일이 없는 건은 이행 목록을 만들어 보완해야 한다. 예상 공수는 0 이상 160 이하로 유지한다. 고객 이메일은 계속 선택 입력이며 형식 검사를 유지한다. 담당자 필수화는 신규 등록뿐 아니라 수정 시의 서버 검증에도 적용해야 한다.

[R2-03] 완료 근거 강화
대기, 진행, 완료 상태는 유지한다. 진행에서 완료로 바꾸거나 완료 상태의 내용을 수정할 때 처리 내용이 비어 있으면 저장을 차단한다. 완료 메모에는 조치 내용과 남은 제약을 구분해 작성한다. 기존 완료 건의 빈 메모를 AI가 임의로 채우지 않고 담당자의 보완 대상으로 표시한다.

[R2-04] 긴급 요청 기준
요청 우선순위를 일반과 긴급으로 구분한다. 일반 요청의 초동 응답은 기존 2영업일 기준을 유지한다. 긴급 요청은 운영 시간 안에서 접수 후 4시간 이내 담당자 배정과 초동 응답을 목표로 한다. 운영 시간은 평일 09:00~18:00 KST로 가정한다. 야간 자동 알림과 휴일 계산은 이번 범위에서 제외하며 운영자에게 검토 항목으로 남긴다.

[R2-05] 조회 및 UAT 추가
담당자별 필터와 마감 임박 필터를 추가한다. 마감 임박은 오늘부터 2일 이내이면서 완료되지 않은 요청이다. 추가 UAT는 담당자 누락, 마감일 누락, 완료 메모 누락, 기존 완료 건 수정, 긴급 요청 표시와 두 필터의 경계값을 포함한다. 화면만 통과해도 서버가 잘못된 값을 받아들이면 결함으로 기록한다.

[R2-06] 영향과 제외 범위
영향 대상은 입력 화면, 레코드 API 검증, 기존 데이터 보완 목록, 인수 테스트, 운영 가이드와 사용자 교육 자료이다. 고객 자동 이메일, 운영 ERP 쓰기 작업, 임의 코드 실행과 대외 배포는 여전히 제외한다. 개발 작업은 별도 작업에서 실제 테스트를 수행하고, 본 변경 비교 결과만으로 구현 완료를 선언하지 않는다.

[R2-07] 확인할 결정
업무 책임자는 기존 데이터 보완 기한과 긴급 요청 분류 권한을 확정해야 한다. QA 담당자는 v1.0 테스트에서 재사용할 항목과 새로 추가할 항목을 구분한다. 운영 담당자는 4시간 응답 목표를 실제 계약 기준으로 채택할 수 있는지 따로 검토한다.
